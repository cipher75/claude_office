# 긴 Codex 기록을 반복 파싱하면 이벤트 처리가 느려질 수 있음

**증상** — Codex hook마다 기록 파일 전체를 최대 두 번 읽고 JSONL을 파싱하며, 기록이 늘어날 때도 같은 작업을 반복한다.

**확인한 근거** — 2026-11-08 Claude 검토에서 이 PC의 13MB 기록을 Node로 한 번 읽고 처리하는 데 약 35ms가 걸렸다고 보고했다. 이번 세션에서는 측정값을 재측정하지 않았으며, `server.ts`의 수신·감시 경로가 `readCodexTranscript`를 반복 호출하는 것은 코드로 확인했다.

**추정 원인** — 마지막으로 읽은 위치와 파싱한 호출 결과를 보관하지 않아 같은 과거 줄을 계속 해석한다.

**시도한 조치** — 이번 수정은 hook 유실 시 실행 결과 복구와 화면 표시를 다뤘다. 기록 읽기 비용의 최적화는 후속 범위로 두었다.

**다음 확인** — 긴 세션에서 hook 수신 지연을 측정하고, 최초 설정 복구 후 새로 붙은 완성된 줄만 처리하도록 바꾼다. 파일 축소·교체와 부분 줄 처리도 기존 감시 로직을 기준으로 검증한다.
